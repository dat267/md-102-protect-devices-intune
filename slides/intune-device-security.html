Pillar one

Compliance & remediation

Prove device health, then fix what's broken before users are blocked.

The core distinction

Profiles enforce

  • Turn on BitLocker
  • Set firewall rules
  • Configure Wi-Fi

Configuration profiles push the desired settings to the device.

The core distinction

Compliance verifies

  • Is BitLocker actually active?
  • Is the OS current?
  • Is antivirus running?

Compliance policies check real state and flag the device Compliant or Noncompliant.

RULE Use both.
Configuration profile: settings pushed to a device. Compliance policy: rules Intune checks and reports on.

Beyond static checks

Static checks miss an active compromise.

A device can have a strong password and the latest OS and still be exfiltrating data right now.

Risk-based evaluation

Defender for Endpoint runs continuously and assigns a machine risk score:

ClearLowMediumHigh

Intune reads that score. You set the bar, for example: require risk at or below Low.

IMPACT Risk goes High, Intune flips compliance immediately, no wait for check-in.
MDE (Microsoft Defender for Endpoint): endpoint security service that scores device risk. Risk score: Clear, Low, Medium, High.

Targeting

Apply the right policy to the right devices

Creating the policy is half the job. Deciding who gets it is the other half.

Entra groups

Assign to User groups (follows the person across devices) or Device groups (locked to hardware like kiosks).

Include + Exclude, e.g. all users except a pilot group.

Dynamic groups

Rule-based membership, e.g. user.department -eq "Engineering". Membership updates automatically as attributes change.

A group holds users or devices, not both.

Assignment filters

Granular targeting without a group per variation, e.g. only corporate-owned iOS devices.

Avoids group bloat.

Entra group: a Microsoft Entra ID security group. Dynamic group: membership driven by attribute rules. Assignment filter: a device-level rule applied at assignment time, so no extra group is needed.

Enforcement

Actions for noncompliance: a graduated timeline

Don't block brutally on day one. Escalate in phases so users can fix issues.

  • Day 0Mark noncompliant. Conditional Access instantly blocks corporate resources.
  • Day 0-1Email the user (optionally CC manager or helpdesk) with steps to fix the problem.
  • Day 1Push notification to the Company Portal app on mobile devices.
  • Day 30+Retire the device. If it stays noncompliant, Intune wipes corporate data from the hardware.

Self-healing

Fix it before the user is blocked

Devices self-heal in the background, so helpdesk tickets and user disruption both drop.

Declarative fixes

Configuration profiles re-apply desired settings and silently correct drift, e.g. re-enable a disabled firewall.

Custom fixes

Intune Remediations: PowerShell detection and remediation scripts that find and fix specific problems.

Target remediation precisely with assignment filters, for example only devices missing a required update.

Intune Remediation: a PowerShell detection plus remediation script. Declarative: desired-state configuration that re-applies automatically.

Pillar two

Microsoft Tunnel

Zero-trust access to on-premises resources from mobile devices.

The problem

On-demand access, not an always-on VPN.

Always-on VPN drains battery, hurts performance, and grants broad network access.

What Microsoft Tunnel is

A cloud-managed VPN gateway giving secure, on-demand access to on-premises resources.

Enrolled + BYOD

Works for enrolled Android Enterprise and iOS/iPadOS devices, and unenrolled BYOD via MAM.

Consider the alternative

For greenfield private access with no Tunnel infrastructure, compare Microsoft Entra Private Access (identity-based ZTNA).

VPN: virtual private network. BYOD: bring your own device. MAM: mobile application management. ZTNA: zero trust network access.

Pillar three

Microsoft Cloud PKI

Certificate identities and automation, without on-premises infrastructure.

The shift

Traditional on-premises PKI

  • NDES server
  • Intune certificate connector
  • CA infrastructure to patch and monitor
  • Emergency response when it goes offline

The shift

Microsoft Cloud PKI

  • Certification authorities created in the Intune admin center
  • No servers, no connectors, no NDES
  • Built-in SCEP service on each issuing CA
  • Available in the Intune Suite or as an add-on
PKI: public key infrastructure. NDES: Network Device Enrollment Service. CA: certification authority. SCEP: Simple Certificate Enrollment Protocol.

Automation

The certificate lifecycle handles itself

1

Key generated locally

The private key is created on the device and never leaves it.

2

CSR to Cloud PKI

The device submits a certificate signing request.

3

Certificate returned

Cloud PKI signs and returns the certificate.

4

Automatic renewal

Renews before expiry, no admin action.

  • Admins configure the SCEP profile once; devices do the rest.
  • Renewal threshold controls how early renewal triggers: use 30-40% for remote devices that check in infrequently.
  • Profiles set subject, SAN, validity, key usage, and EKUs. Deploy the trusted cert profile first, then SCEP.
CSR: certificate signing request. SAN: subject alternative name. EKU: extended key usage. Renewal threshold: the percent of validity at which renewal starts.

Governance

Know the state of every certificate.

Visibility and accountability

  • Cloud PKI dashboard and Devices > Monitor > Certificates show Active, Expired, and Revoked states.
  • Reports update every 24 hours; the Devices monitor has no 1,000-record limit.
  • Audit logs record CA creation, revocations, and property changes.
TIP Build proactive alerts so failures surface before users hit them.
CRL: certificate revocation list. Audit log: a record of administrative actions.

Recap

Key takeaways

1 Configuration profiles enforce; compliance policies verify. Use both.
2 Layer risk-based signals from Defender on top of static checks.
3 Scope with groups and assignment filters; escalate noncompliance gradually.
4 Remediate automatically so devices self-heal before users are blocked.
5 Tunnel gives on-demand zero-trust access; Cloud PKI automates device identity.
